# M03 GENERATOR SPEC
## Программный генератор сложения многозначных чисел

Версия документа: 1.0  
Статус: TECHNICAL CONTRACT  
Дата: 2026-08-22

| Поле | Значение |
|---|---|
| Навык | M03 |
| Канонический `skillId` | `math.calculation.multi_digit.addition` |
| Название | Сложение многозначных чисел |
| Генератор | `gen.math.multi_digit.addition` |
| Источник | `generated` |
| Текущая задача | генерация уровней 1–3 |
| Уровни 4–5 | пока не генерируются программно |

Краткий код `M03` не является `skillId`. В задании всегда пишется канонический ID.

Источник педагогических границ: карточка M03 в `CONTENT_MATRIX_MATH.md` (версия 2.0, заморожена). Этот документ не заменяет матрицу и не меняет каталог M01–M35. Он задаёт инженерный контракт генератора.

Публичный API:

- `generateM03Task`
- `generateM03Series`

Тип задания: существующий `Task`. Параллельная модель не создаётся.

---

# 1. Общие правила

1. Генератор создаёт задания только по M03.
2. Каждое задание обязано содержать:
   - `skillId = math.calculation.multi_digit.addition`
   - `subject = mathematics`
   - `sourceType = generated`
   - `generatorId = gen.math.multi_digit.addition`
   - `difficulty = 1 | 2 | 3`
3. Правильный ответ всегда вычисляется программно из фактических слагаемых.
4. Нельзя доверять заранее заданному правильному ответу.
5. Один и тот же набор `seed + difficulty + subtype` даёт одно и то же задание.
6. В серии не должно быть дубликатов (одинаковый набор слагаемых в том же порядке).
7. Генератор не должен создавать задание с математической сложностью ниже заявленного уровня.
8. Простое увеличение количества цифр само по себе не считается достаточным усложнением.
9. Не использовать искусственные варианты ответов вроде «правильный ответ ± 100», если такая ошибка не соответствует реальной разрядной ошибке ученика.
10. Все ограничения проверяются программно после построения чисел. Если проверка не проходит, задание не возвращается, а пересобирается.

Дополнительно:

- не использовать `Math.random()`;
- воспроизводимость только через `seededRng`;
- уровни 4 и 5 завершаются контролируемой ошибкой;
- двузначные примеры не являются основным форматом M03 для 4 класса.

---

# 2. Порядок генерации

Правильный порядок:

1. Выбрать структуру задания по уровню и подтипу.
2. Зафиксировать параметры: число слагаемых, разрядность, план переносов, нули, разную разрядность.
3. Построить числа по этой структуре.
4. Программно измерить переносы и признаки.
5. Принять или отбросить.

Неправильный порядок:

`случайные числа → посчитать переносы → назвать уровнем`

---

# 3. Уровень 1

Цель: закрепление обычного сложения многозначных чисел.

Правила:

- ровно 2 слагаемых;
- слагаемые преимущественно 3–4-значные;
- не использовать двузначные примеры как основной вариант L1;
- допустимая разрядность: `3+3`, `3+4`, `4+3`, `4+4`;
- допускается 0 переносов;
- допускается ровно 1 перенос;
- не допускается 2 и более переносов;
- не использовать одновременно несколько дополнительных усложнений.

Подтипы L1:

- `no_carry` — одинаковая разрядность, 0 переносов;
- `carry_one` — одинаковая разрядность, ровно 1 перенос;
- `mixed_digits` — разная разрядность, без второго усложнения (без нескольких переносов). Основной формат: `4+3` или `3+4`.

Примеры подходящего уровня: `234 + 125`, `432 + 156`, `843 + 110`.  
`914 + 45` допустим только как контролируемый `mixed_digits`, не как основной формат L1.

Не создавать как обычные задания L1: `55 + 34`, `43 + 55`, `48 + 12`.

Инженерная проверка L1:

- `addends.length === 2`
- каждый элемент `digitCounts` равен 3 или 4
- `carryCount <= 1`
- для `no_carry`: `carryCount === 0` и разрядность одинаковая
- для `carry_one`: `carryCount === 1` и разрядность одинаковая
- для `mixed_digits`: разрядность разная и `carryCount <= 1`

---

# 4. Уровень 2

Цель: самостоятельное сложение многозначных чисел с несколькими переносами.

Правила:

- ровно 2 слагаемых;
- преимущественно 3–4-значные числа;
- минимум 2 переноса;
- желательны последовательные переносы;
- допустимы нули, если они не делают задание искусственным;
- допускается разная разрядность;
- задание должно быть объективно сложнее типичного L1.

Основные подтипы L2:

- `carry_many`
- `with_zeros`
- `mixed_digits`

Минимальное правило: `carryCount >= 2`.

Чтобы L2 не совпадал с L3, инженерно фиксируется:

- типичный L2 имеет **ровно 2 переноса**;
- эти два переноса последовательные (единицы и десятки).

Не создавать L2, математически равное обычному L1, только под другим номером уровня.

Запрещённый класс совпадения:

- одинаковая разрядность;
- одинаковое число слагаемых;
- одинаковая структура переносов (`0` или `1` перенос).

Пример запрещённой пары:

- L1: `866 + 115`
- L2: `756 + 128`

Инженерная проверка L2:

- `addends.length === 2`
- каждый элемент `digitCounts` равен 3 или 4
- `carryCount === 2`
- есть последовательные переносы
- задание не проходит проверку L1

---

# 5. Уровень 3

Цель: более сложные варианты многозначного сложения. L3 добавляет новый фактор сложности, а не просто увеличивает числа.

Разрешённые конструкции:

A. Три слагаемых, например `2487 + 936 + 1578`  
B. Два слагаемых с несколькими переносами, например `4876 + 6958`  
C. Нули внутри многозначных чисел, например `6048 + 2976`  
D. Разная разрядность, например `5278 + 846`  
E. Комбинация нескольких факторов.

Для трёх слагаемых минимальная разумная разрядность: каждое слагаемое не короче 3 цифр. Запрещён класс `108 + 49 + 290`.

L3 с двумя слагаемыми должен иметь хотя бы один дополнительный фактор по сравнению с типичным L2. Недостаточно:

- большее число при той же структуре;
- другой seed;
- другой ответ.

Дополнительный фактор для двух слагаемых L3 — одно из:

- `carryCount >= 3`;
- нули внутри **и** несколько переносов сверх типичного L2;
- разная разрядность **и** `carryCount >= 3`.

Инженерная проверка L3:

- либо `addends.length === 3`, каждое слагаемое 3–4-значное, `carryCount >= 2`;
- либо `addends.length === 2`, слагаемые 3–4-значные, и есть фактор сверх типичного L2 (`carryCount >= 3` и/или комбинация нулей, разной разрядности и цепочки переносов);
- задание не проходит проверку L1 и не является типичным L2 (`carryCount === 2` без третьего фактора).

Не допускать, чтобы L3 оказывался легче хорошего L2.

---

# 6. Подтипы и признаки

Основные подтипы (не навыки, не новые `skillId`):

- `no_carry`
- `carry_one`
- `carry_many`
- `with_zeros`
- `three_addends`
- `mixed_digits`

Главный `subtype` отражает основной фактор задания.

Дополнительные признаки хранятся в `features` и не становятся отдельными навыками.

`generatorParams`:

```text
addends
carryCount
digitCounts
hasZeros
subtype
features
seed
```

Примеры:

- `subtype = "with_zeros"`, `features = ["carry_many", "consecutive_carries"]`
- `subtype = "mixed_digits"`, `features = ["carry_many"]`

Допустимый технический признак в `features`: `consecutive_carries`.

Если запрошенный подтип соответствует фактам, он сохраняется как главный, даже если есть и другие признаки (например L1 `no_carry` с нулём внутри: `843 + 110`).

---

# 7. Правила дистракторов

Типы заданий:

- L1 и L2: `singleChoice`, ровно 4 варианта, ровно 1 правильный;
- L3: `numberAnswer`, правильный ответ — однозначное число суммы.

Нельзя полагаться преимущественно на `answer ± 1`, `answer ± 10`, `answer ± 100` как на заполнитель.

Категории ошибок:

| Код | Смысл |
|---|---|
| `forgot_carry` | забытый перенос |
| `wrong_column` | сдвиг разрядов / неверное выравнивание столбика |
| `place_value_error` | ошибка разрядности (потеря старшего разряда, перенос не в тот разряд) |
| `digit_addition_error` | ошибка сложения цифр в одном разряде |

Если осмысленный дистрактор данной категории для конкретного задания построить нельзя, берётся другой корректный тип. Нельзя подставлять случайное число без педагогического смысла.

Каждый дистрактор:

- отличается от правильного ответа;
- является положительным целым числом;
- не совпадает с другим дистрактором;
- воспроизводится от seed.

`answer ± 100` допустим только если это следствие разрядной ошибки (например ошибка цифры в сотнях), а не искусственный сдвиг.

Фильтр правдоподобия: дистрактор отклоняется, если число разрядов отличается более чем на 1 от суммы или значение вне примерно `0.65×…1.55×` правильного ответа (типичный артефакт — «левое» выравнивание смешанных слагаемых). Лучше другой допустимый тип ошибки, чем искусственный вариант.

---

# 8. Проверка сложности после генерации

Генератор измеряет факты по построенным числам:

- число слагаемых;
- `digitCounts`;
- точное `carryCount`;
- наличие последовательных переносов;
- нули внутри записи числа;
- разная разрядность;
- сумма слагаемых.

Если факты не соответствуют уровню или запрошенному подтипу:

- задание не возвращается;
- генерация повторяется на том же RNG (следующая попытка).

Переносы считаются точно по столбцам справа налево, с учётом входящего переноса. Приблизительно считать нельзя.

---

# 9. Проверка качества серии

`generateM03Series` проверяет:

- отсутствие дубликатов слагаемых;
- корректный `skillId`;
- корректный `difficulty`;
- соответствие подтипа фактической структуре;
- соответствие `carryCount`;
- соответствие `digitCounts`;
- правильность ответа как суммы;
- соответствие типа задания уровню;
- отсутствие заданий, которые проходят проверку более низкого уровня.

Формальное доказательство «сложности» не требуется. Нужны разумные инженерные ограничения из §3–§5.

Тестовая серия (dev): 10 + 10 + 10 заданий. В `MATH_TASKS` не попадает.

---

# 10. Seed

- не использовать `Math.random()`;
- `createSeededRng(seed)` — единственный источник случайности;
- одинаковые `seed + difficulty + subtype` → одинаковое задание;
- одинаковый seed серии → одинаковая серия.

---

# 11. Уровни 4–5

Пока не генерировать.

`generateM03Task({ difficulty: 4 })` и `generateM03Task({ difficulty: 5 })` завершаются контролируемой ошибкой с понятным сообщением.

Причина: уровни 4–5 требуют отдельной спецификации формата и шаблонов, а не простого увеличения чисел.

---

# 12. Что генератор не делает

- не меняет `CONTENT_MATRIX_MATH.md`;
- не меняет каталог M01–M35;
- не создаёт M04 и другие генераторы;
- не пишет задания в production-банк `MATH_TASKS`;
- не подключает AI, сервер, БД и внешние API;
- не вводит новые `skillId` для подтипов и `features`.
