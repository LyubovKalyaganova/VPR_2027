# MASTERY SPEC
## SkillMastery, masteryScore и адаптивное повторение
### Приложение «Персональный тренажёр к ВПР 4 класса»
Версия документа: 1.0  
Статус: SPECIFICATION / PROJECT DECISION  
Этап: 6А  
Дата: 2026-08-20
---
# 1. Назначение
Этот документ описывает правила расчёта освоения навыков (`SkillMastery`), определения слабых мест ребёнка, интервального повторения и адаптивного выбора заданий.
Документ является спецификацией поведения приложения.
На этапе 6А никакая логика из этого документа не реализуется в коде.
Существующие:
- `Attempt`
- `TaskEngine`
- `TaskSession`
- `taskRepository`
- `useTrainingStore`
- `LocalAttemptRecorder`
- UI
не изменяются.
---
# 2. Основная идея
Приложение не должно считать прогресс только как процент правильных ответов.
Например:
Ребёнок решил 1 задание правильно.
Это ещё не означает, что навык освоен.
Поэтому для каждого навыка используется отдельное состояние:
`SkillMastery`
Оно учитывает:
- историю попыток;
- правильность;
- сложность задания;
- использование подсказок;
- давность попытки;
- количество попыток;
- последовательность правильных и неправильных ответов;
- интервальное повторение.
Основной показатель:
`masteryScore`
Диапазон:
`0–100`.
---
# 3. Уровни освоения навыка
Используются четыре состояния.
| Диапазон masteryScore | Состояние |
|---|---|
| 0–39 | `not_mastered` |
| 40–59 | `developing` |
| 60–79 | `confident` |
| 80–100 | `mastered` |
Дополнительно навык может иметь состояние:
`new`
если по нему ещё нет ни одной попытки.
`new` не является числовым уровнем и означает отсутствие истории.
---
# 4. Интерфейс SkillMastery
На концептуальном уровне `SkillMastery` содержит:
```ts
interface SkillMastery {
  userId: string;
  skillId: string;
  masteryScore: number;
  attemptsCount: number;
  correctCount: number;
  incorrectCount: number;
  lastAttemptAt: string | null;
  lastCorrectAt: string | null;
  currentStreak: number;
  incorrectStreak: number;
  lastDifficulty: number | null;
  lastHintsUsed: number;
  nextReviewAt: string | null;
  reviewIntervalDays: number;
  status: 'new' | 'not_mastered' | 'developing' | 'confident' | 'mastered';
}
```
---
# 5. Диапазон masteryScore
score всегда находится в диапазоне:
0...100
Где:
0–19 — навык практически не освоен;
20–39 — начальный уровень;
40–59 — формирующийся навык;
60–74 — базовое освоение;
75–89 — хороший уровень;
90–100 — устойчивое освоение.
Это не школьная оценка и не баллы ВПР.
Это внутренний показатель адаптивного тренажёра.
---
# 6. Формула masteryScore
Для MVP использовать понятную и стабильную формулу.
Основной показатель:
baseScore
рассчитывается по последним попыткам ребёнка.
Для каждого навыка учитывать максимум последние 10 Attempt.
Если попыток больше 10, старые попытки не удаляются из базы, но не участвуют непосредственно в текущем расчёте mastery.
## 6.1. Вес попытки
Более свежие попытки имеют больший вес.
Для последних 10 попыток использовать веса:
| Позиция | Вес |
|---|---|
| самая старая | 0.55 |
| 2 | 0.60 |
| 3 | 0.65 |
| 4 | 0.70 |
| 5 | 0.75 |
| 6 | 0.80 |
| 7 | 0.85 |
| 8 | 0.90 |
| 9 | 0.95 |
| последняя | 1.00 |
Если попыток меньше 10 — использовать только существующие.
---
# 7. Базовый результат попытки
Каждая попытка получает attemptScore.
Правильный ответ:
1
Неправильный ответ:
0
Но на итоговый mastery дополнительно влияют подсказки и сложность.
---
# 8. Влияние подсказок
Подсказки уменьшают вклад правильного ответа, но не превращают его в ошибку.
Для hintsUsed:
| Подсказок | Множитель |
|---|---|
| 0 | 1.00 |
| 1 | 0.90 |
| 2 | 0.80 |
| 3 | 0.70 |
Если правильный ответ получен после 2 подсказок:
attemptScore = 1 × 0.80 = 0.80
Если ответ неправильный:
attemptScore = 0
Количество подсказок учитывается только как снижение качества правильного результата.
---
# 9. Влияние сложности
Сложность задания:
1–5.
На этапе MVP сложность НЕ должна напрямую давать дополнительные 20–30 баллов mastery.
Она используется для определения уровня уверенности.
Использовать коэффициент:
| Difficulty | Коэффициент |
|---|---|
| 1 | 0.90 |
| 2 | 0.95 |
| 3 | 1.00 |
| 4 | 1.05 |
| 5 | 1.10 |
Формула:
adjustedAttemptScore = attemptScore × difficultyCoefficient
Значение ограничивается максимумом 1.
То есть правильный ответ на сложном задании может дать немного больший вклад, но не более 100%.
---
# 10. Итоговый masteryScore
Для каждой попытки:
attemptValue =
  correctness
  × hintMultiplier
  × difficultyCoefficient
Затем:
weightedScore =
  Σ(attemptValue × recencyWeight)
  /
  Σ(recencyWeight)
И:
masteryScore = round(weightedScore × 100)
Всегда ограничивать:
0 <= masteryScore <= 100
---
# 11. Минимальная защита от слишком быстрых 100%
Нельзя считать навык полностью освоенным после одного правильного ответа.
Правило:
если количество попыток < 3:
masteryScore не может быть выше 60.
если количество попыток < 5:
masteryScore не может быть выше 80.
После 5 и более попыток ограничение снимается.
Пример:
1 правильный ответ:
score <= 60
3 правильных ответа:
score <= 80
5+ стабильных правильных ответов:
может достигнуть 90–100.
---
# 12. Ошибки
Ввести типы ошибок.
На уровне MVP использовать:
```ts
type ErrorType =
  | 'wrongAnswer'
  | 'careless'
  | 'calculation'
  | 'concept'
  | 'unit'
  | 'reading'
  | 'unknown';
```
Однако НЕ пытаться автоматически определять точный тип ошибки из одного неправильного ответа.
Если система не может достоверно определить причину:
errorType = 'unknown'
---
# 13. Как определять ошибки на MVP
Для numberAnswer:
если ответ неправильный:
wrongAnswer
Если в дальнейшем появится анализ ответа, можно уточнять:
calculation
unit
concept
Для singleChoice:
неправильный ответ:
wrongAnswer
Для сложных типов:
unknown
Не создавать искусственную классификацию ошибок только ради заполнения поля.
---
# 14. Последовательные ответы
Хранить:
consecutiveCorrect
и:
consecutiveIncorrect
После правильного ответа:
consecutiveCorrect += 1
consecutiveIncorrect = 0
После ошибки:
consecutiveIncorrect += 1
consecutiveCorrect = 0
Это будет использоваться системой интервального повторения.
---
# 15. Интервальное повторение
Использовать три основных интервала:
сразу;
1 день;
3 дня;
7 дней.
---
# 16. Правила повторения после ошибки
Если ребёнок ошибся:
nextReviewAt = сейчас
reviewIntervalDays = 0
Такой навык должен считаться кандидатом на повторение практически сразу.
Если ребёнок снова ошибся:
интервал остаётся:
0 дней
---
# 17. Правила после правильного ответа
Использовать последовательность:
Первый правильный ответ
interval = 1 день
Второй правильный ответ подряд
interval = 3 дня
Третий и последующие правильные ответы подряд
interval = 7 дней
После достижения 7 дней:
при стабильных правильных ответах интервал остаётся 7 дней на этапе MVP.
Не увеличивать его до 14, 30 и т.д. без отдельной спецификации.
---
# 18. Влияние подсказок на интервалы
Правильный ответ после подсказки считается правильным для consecutiveCorrect, но качество освоения ниже.
Если использована хотя бы одна подсказка:
не увеличивать интервал быстрее следующего шага.
Например:
было 1 день → правильный ответ с подсказкой → оставить 1 день.
Это не позволяет ребёнку быстро получить 7-дневный интервал, постоянно используя подсказки.
---
# 19. Сильный навык
Навык считается устойчиво освоенным, если одновременно:
masteryScore >= 90
и:
consecutiveCorrect >= 3
и последняя попытка выполнена:
без подсказок
Только после выполнения всех трёх условий навык считается mastered.
---
# 20. Слабый навык
Навык считается слабым, если:
masteryScore < 60
или:
consecutiveIncorrect >= 2
или:
последняя попытка неправильная
Приоритет должен иметь последнее неправильное выполнение.
---
# 21. Приоритет слабых мест
Для будущего режима weak использовать такой порядок:
Последняя попытка неправильная.
masteryScore < 40.
consecutiveIncorrect >= 2.
Самый низкий masteryScore.
Навык давно не повторялся.
Не выбирать задания только случайным образом.
---
# 22. Приоритет повторения
Для режима повторения сначала выбирать:
Приоритет 1
Навыки, у которых:
nextReviewAt <= now
Приоритет 2
Навыки с последней ошибкой.
Приоритет 3
Навыки с низким mastery.
Приоритет 4
Навыки, которые давно не тренировались.
---
# 23. Не создавать бесконечное повторение
Если ребёнок много раз подряд ошибается на одном навыке, система не должна бесконечно показывать только его.
В одной тренировке:
максимум 2 задания подряд одного skillId;
затем можно добавить задания другого навыка;
проблемный навык возвращается позже.
Это предотвращает ощущение «застрял на одной теме».
---
# 24. Связь с Difficulty
Адаптивная система должна учитывать текущую сложность.
Если:
masteryScore < 40
рекомендуется:
difficulty 1–2
Если:
40 <= masteryScore < 70
рекомендуется:
difficulty 2–3
Если:
70 <= masteryScore < 90
рекомендуется:
difficulty 3–4
Если:
masteryScore >= 90
можно использовать:
difficulty 4–5
Но если в банке нет заданий нужной сложности, брать ближайшую доступную сложность.
---
# 25. Важное правило для текущего банка
Текущий банк MATH_TASKS содержит только задания сложности 1–3.
Поэтому адаптивный алгоритм НЕ должен считать отсутствие заданий сложности 4–5 ошибкой.
Если нужной сложности нет:
использовать доступную.
---
# 26. Прогресс темы
Прогресс темы не хранить как отдельное число на первом этапе.
Вычислять его из SkillMastery.
Если тема содержит несколько навыков:
topicScore =
average(skill.masteryScore)
Учитывать только навыки, по которым есть хотя бы одна Attempt.
Если по теме нет попыток:
topicScore = null
Не показывать 0%, потому что ребёнок ещё не начинал тему.
---
# 27. Прогресс раздела
Аналогично:
sectionScore =
average(topicScores)
Учитываются только темы с реальными попытками.
---
# 28. Прогресс предмета
Для математики:
subjectScore =
average(all mastered/attempted skill scores)
Только навыки, по которым есть Attempt.
Не считать отсутствующие навыки нулём.
Иначе новый ребёнок получит искусственно низкий прогресс из-за большого ещё не изученного банка.
---
# 29. Новый ребёнок
Если нет ни одной Attempt:
masteryScore = null
а не:
masteryScore = 0
Это принципиально важно.
0 означает:
навык проверен и пока не освоен.
null означает:
навык ещё не проверялся.
---
# 30. DEMO-задания
DEMO-задания без skillId:
сохраняются в Attempt;
не участвуют в SkillMastery;
не влияют на адаптивный прогресс;
не влияют на слабые места.
Это позволяет постепенно отказаться от DEMO без загрязнения реальной статистики ребёнка.
---
# 31. Реальная ВПР
Задания sourceType: 'vpr' в будущем должны также иметь:
skillId;
topicId;
difficulty;
vprVersion.
Результат пробной ВПР может использоваться для диагностики SkillMastery, но отдельные правила экзамена будут описаны в спецификации режима exam.
Не реализовывать это сейчас.
---
# 32. Offline-first
SkillMastery должен работать полностью без интернета.
Источник данных:
Attempt из локального хранилища.
Никаких:
API;
облачных вычислений;
внешних сервисов;
аналитики.
---
# 33. Архитектура
Не помещать расчёт SkillMastery в React-компоненты.
Рекомендуемая архитектура:
Attempt
   ↓
MasteryCalculator
   ↓
SkillMastery
   ↓
Progress selectors
   ↓
UI
Создать отдельный модуль расчёта.
Например:
src/engine/mastery/
Предполагаемые файлы:
masteryCalculator.ts
masteryTypes.ts
masteryUtils.ts
Названия можно изменить только при необходимости.
---
# 34. Важное требование
Не изменять существующий TaskEngine без необходимости.
Не дублировать запись Attempt.
Не изменять формат уже существующих Attempt так, чтобы старые сохранённые данные перестали читаться.
---
# 35. Совместимость со старым хранилищем
Приложение уже может иметь сохранённые Attempt старого формата.
Новый код должен корректно работать с ними.
Если отсутствуют:
topicId
skillId
они трактуются как:
undefined
Такие попытки просто не участвуют в SkillMastery.
Не удалять старые Attempt.
---
# 36. Точность дат
date, lastAttemptAt и nextReviewAt хранить в ISO-формате.
Например:
2026-08-20T12:30:00.000Z
Для сравнения использовать timestamp.
Для отображения пользователю использовать локальное время устройства.
---
# 37. Не использовать таймер как штраф
timeSpent сохранять и использовать для статистики.
На этапе MVP:
время НЕ должно уменьшать masteryScore.
Причина:
медленный ребёнок не должен автоматически считаться хуже освоившим навык.
В дальнейшем можно отдельно исследовать нормативы времени.
---
# 38. Основная цель этапа 6
После реализации этого документа система должна уметь ответить:
Какие навыки ребёнок уже проверял?
Какие навыки освоены хорошо?
Какие навыки слабые?
Какой навык нужно повторить сейчас?
Когда его повторить?
Какую сложность задания предложить?
Какой общий прогресс по теме?
Какой прогресс по математике?
---
# 39. Что НЕ реализовывать на этапе 6
Не добавлять:
сервер;
API;
авторизацию;
облачную синхронизацию;
рекламу;
платежи;
AI;
аналитику;
Capacitor;
SQLite;
кабинет родителя;
реальные задания ВПР;
новые математические генераторы.
Эти задачи относятся к следующим этапам.
---
# 40. Критерии готовности
Этап 6А считается завершённым, если:
этот документ существует в корне проекта;
формула masteryScore зафиксирована;
правила подсказок зафиксированы;
правила сложности зафиксированы;
типы ошибок зафиксированы;
интервалы 0/1/3/7 дней зафиксированы;
правила weak/mastered зафиксированы;
определено поведение для нового ребёнка;
DEMO не влияет на SkillMastery;
старые Attempt остаются совместимыми;
не изменён код приложения.
