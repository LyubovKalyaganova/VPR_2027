# 2. Граница навыка

## Относительно соседей

| Сосед | Граница |
|---|---|
| M03–M07 | отдельные арифметические действия / столбик; **не** порядок в выражении |
| M08 | значение **числового выражения** с учётом приоритета и скобок |
| M09+ | величины и прочее — вне M08 |

Если ученик выбрал верный порядок, но ошибся в арифметике — педагогически это ещё и M03–M06;  
`skillId` задания всё равно **M08**, если цель — выражение.

## Что умеет ученик

- соблюдать приоритет: `×` / `:` раньше `+` / `−`;
- выполнять действия одного приоритета слева направо;
- учитывать скобки;
- получить **числовое** значение выражения.

## Что НЕ относится к M08 (L1–L3 генератор)

- формат ВПР (L4);
- упорядочивание шагов как основной ответ (L5 / `ordering`);
- сравнение с «чужим» готовым решением как основной формат;
- многозначный столбик как цель (числа держатся малыми, чтобы не подменять навык);
- отрицательные промежуточные и итоговые значения;
- деление с остатком внутри выражения;
- вложенные скобки `((…))`.

**Неоднозначность карточки (зафиксирована консервативно):**

1. Подтипы «указать, какое действие первым» и «сравнить с чужим решением» относятся к альтернативным форматам / L5;  
   в L1–L3 генератор отвечает **числом** (`singleChoice` / `numberAnswer`), как M03–M07.
2. «Два-три действия одного приоритета» допускает и `+ −`, и `× :`; оба входят в L1 как разные subtype.
3. TaskType в матрице: `numberAnswer`, `fillBlank`, `ordering`.  
   Для тренировочной серии L1/L2 используем `singleChoice` (согласовано с M03–M07), L3 — `numberAnswer`.

# 3. Уровни (структура, не «длина числа»)

Уровень = заранее выбранная **структура выражения**.

## L1 — один приоритет

- 2 или 3 бинарных действия;
- **все** операции одного приоритета:
  - только `+` / `−`, **или**
  - только `×` / `:`;
- **без** скобок;
- **без** смеси низкого и высокого приоритета;
- итог и все осмысленные промежуточные результаты — целые **> 0**;
- деление только нацело.

Примеры структур: `a + b − c`, `a − b + c`, `a × b ÷ c`, `a × b × c`.

## L2 — смешанный приоритет без скобок

- без скобок;
- есть **хотя бы одна** операция `×` или `:`;
- есть **хотя бы одна** операция `+` или `−`;
- 2 или 3 действия;
- верный порядок: сначала `×`/`:`, затем `+`/`−` (слева направо внутри приоритета);
- итог > 0, деление нацело, без отрицательных промежуточных там, где вычитание.

Примеры: `a + b × c`, `a × b − c`, `a − b × c` (при `a > b×c`), `a × b + c − d` (3 действия).

## L3 — скобки, 3–4 действия

- есть **непустые** скобки, меняющие или фиксирующие порядок относительно «без скобок»;
- суммарно **3 или 4** бинарных действия;
- скобки **содержательны**: значение с скобками **отличается** от наивного «всё слева направо без учёта приоритета **или**» от вычисления с проигнорированными скобками (хотя бы один из ложных порядков даёт другой результат — предпочтительно оба);
- запрещены избыточные скобки вида `a + (b × c)`, если они не меняют значение относительно `a + b × c` **и** не создают отличия от left-to-right — такие шаблоны не генерировать;
- итог > 0, деление нацело.

Примеры: `(a + b) × c`, `a × (b − c)`, `(a + b) × c − d`, `a + (b − c) × d`.

## Взаимное исключение

| | L1 | L2 | L3 |
|---|---|---|---|
| скобки | нет | нет | да |
| смесь приоритетов | нет | да | допускается |
| один приоритет | да | нет | не как единственный признак L1 |

`isValidM08Level` проверяет структуру по токенам/AST, а не длину записи.

L4/L5: `generateM08Task` **бросает ошибку**.

# 4. Подтипы и features

Подтип — **вид выражения**, не уровень.

| subtype | Уровни | Смысл |
|---|---|---|
| `same_priority_add_sub` | L1 | только `+`/`−` |
| `same_priority_mul_div` | L1 | только `×`/`:` |
| `mixed_no_parens` | L2 | смесь приоритетов без скобок |
| `with_parens` | L3 | выражение со скобками |

`features` (дополнительно, без дубля subtype):

- `two_ops` / `three_ops` / `four_ops`
- `has_multiplication` / `has_division` / `has_addition` / `has_subtraction`
- `left_to_right_trap` — left-to-right без приоритета даёт другой ответ
- `parens_change_value` — игнор скобок даёт другой ответ
- `exact_division` — в выражении было деление нацело

# 5. generatorParams

```text
expression        // строка условия, напр. "7 + 3 × 4"
tokens            // сериализуемые токены для независимой проверки
opsCount          // число бинарных операций
hasParens         // boolean
priorities        // 'same_add_sub' | 'same_mul_div' | 'mixed'
subtype
features
value             // справочно; истина = независимый пересчёт
seed
```

Правильный ответ = независимое вычисление `tokens`, не доверять полю `value`.

# 6. Алгоритм генерации

1. Выбрать уровень → subtype.
2. Выбрать шаблон структуры (какие операции / где скобки).
3. Подобрать малые целые операнды (таблица 2–9 для `×`/`:`; двузначные умеренные для `+`/`−`) так, чтобы инварианты выполнялись.
4. Собрать токены и строку выражения.
5. Независимо вычислить значение.
6. Проверить `isValidM08Level` и взаимное исключение.
7. Для L1/L2 — дистракторы с моделями ошибок; L3 — `numberAnswer`.
8. Собрать `Task`.

Числа:

- множители/делители: преимущественно 2–9;
- слагаемые/вычитаемые: в основном 2–40, чтобы навык был про порядок, не про столбик;
- произведение промежуточных шагов обычно ≤ 200;
- частное целое.

# 7. Независимая проверка

После сборки:

- `skillId`, `generatorId`, `topicId`, `sourceType`, `difficulty` ∈ {1,2,3};
- `correctAnswer` === `evaluateExpression(tokens)`;
- `isValidM08Level(tokens, difficulty)`;
- не проходит другие уровни;
- нет `Math.random` в генераторе;
- деление только нацело на каждом шаге, где оно есть;
- значение > 0.

---

# 8. Дистракторы

L1/L2: `singleChoice`, 4 варианта, 1 правильный.  
L3: `numberAnswer`.

Модели (приоритет):

1. **left_to_right** — все действия слева направо, игнор приоритета;
2. **ignore_parens** — скобки сняты, дальше обычный приоритет (L3; на L2 не применимо);
3. **add_first** — сначала все `+`/`−`, потом `×`/`:` (типичная путаница);
4. **first_op_only** — результат только первого действия;
5. **arith_slip** — верный порядок, ошибка ±1 или ±10 на финале / соседний табличный факт на одном `×`.

Запрещено: случайные далёкие числа; `1`/`2`/`3` без модели; голый ±100 без модели.

Фильтр: уникальность; ≠ правильному; положительное целое; для «дальних» моделей — не принимать кандидата, если он совпал с правильным; предпочитать значение с числом цифр в пределах ±1 от ответа.

# 9. Seed и серия

- `createSeededRng` / без `Math.random`;
- `generateM08Series({ seed, countPerLevel })` → по `countPerLevel` на L1/L2/L3;
- одинаковый seed → та же серия;
- fingerprint = нормализованная строка выражения.

Тестовая серия (dev): 10+10+10. В `MATH_TASKS` не попадает.
